# 回复编排包

`qunbot.replies` 只负责“这一轮用什么形式回复”，不拥有记忆、情绪、模型、QQ 或媒体供应商。

处理链固定为：

1. `Agent` 在一次模型调用中读取对话、人物关系、长期记忆、情绪和 Skill，并得到 `ReplyDraft`。
2. `ReplyPlanner` 根据当前已注册能力，把模型偏好校验成 `ReplyPlan`。默认实现是确定性的，不调用模型。
3. `ReplyDispatcher` 调用媒体端口解析素材并通过消息端口发送，记录实际送达结果。
4. `ConversationService` 只把实际送达的语义文本写入会话，并把它交给记忆、情绪、好感度等观察者。

扩展新媒介时，不修改 `Agent` 或会话服务：增加一种计划能力和对应 Dispatcher/媒体适配器即可。供应商配置、文件路径和 OneBot action 不得进入模型输出协议。

## 前缀缓存边界

固定人格、Skill 目录和回复 JSON 协议位于首条 system message，进程内保持逐字节不变。用户资料、长期记忆、情绪、可用表情标签和本轮 Skill 都只进入最后的动态上下文。媒介选择复用同一次模型回复，不能再发起“判断该用文字还是语音”的第二次模型调用。

这样，频繁变化的记忆和情绪不会污染可缓存前缀；禁用表情或语音时，也不会创建其客户端或产生供应商请求。计划后的素材失效或 TTS 失败必须由 Dispatcher 降级为文字，不能丢失本轮回复。
