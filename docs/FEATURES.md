# QunBot 功能文档

一个接入 QQ 群的对话 Bot。默认只被 @ 时回复，能记住群里发生的事、认识每个群友、
有自己的心情和表达习惯，可以由部署者按需开启若干拟人化能力。

这份文档按**功能**组织，讲清每项能力做什么、怎么开、配置在哪、以及**它不做什么**。
安装与联网步骤见 [启动指南](QUICKSTART.md)，模块现状与后续方向见
[DEVELOPMENT_ROADMAP](DEVELOPMENT_ROADMAP.md)。

- 文档描述的是当前源码实现，不代表所有服务商与 QQ 客户端组合均已实机验证。
- Pillow、TTS 和 embedding 是可选能力；基础 Python 依赖和可用的聊天模型仍然需要。

---

## 一、两个贯穿全局的设计约束

这两条约束决定了下面每个功能长什么样，先讲清楚。

### 1. 稳定前缀与动态后缀

发给模型的请求被切成两段：

```
[ 稳定前缀 ]  人格 + 已启用 Skill 的目录        ← 每轮字节完全相同，可被服务商缓存
[ 历史对话 ]  最近若干条消息
[ 动态后缀 ]  记忆 / 心情 / 临时性格 / 黑话 / 时间 / 天气 …  ← 每轮都变
[ 当前消息 ]  发言人 + 正文（+ 图片）
```

**任何会变的东西都只能进动态后缀。** 时间戳写进前缀会让缓存彻底失效——这是同类
项目（AstrBot 的 Connectome 插件）踩过的坑，也是这个 Bot 从一开始就避免的。

动态后缀有预算：每个贡献者有自己的字符上限，整体还有总额；额度不够时按优先级
**整条丢弃**，不做截断——半句「关系阶段：亲近。说话可」读起来像坏掉的指令，
不像短指令。某个贡献者抛异常也只是少一条内容，不会让用户收不到回复。

### 2. 信任级别

进动态后缀的每条内容都标注了权威级别，模型会看到：

| 级别 | 来源 | 例子 |
|---|---|---|
| `high` | 部署者配置 | 表情包标签表、本机时钟 |
| `medium` | 模型产出 | 记忆、心情、临时性格、黑话 |
| `low` | 群友输入或外部抓取 | 群消息、第三方天气接口 |

群友打的字**永远是数据，不是指令**——不管它写得多像一条命令。提示词里会明确
告诉模型这一点。

## 二、核心能力（不可关闭）

### 会话与触发

| 场景 | 行为 |
|---|---|
| 群聊被 @ | 未启用回复策略时回复；启用策略后还会经过概率、额度和追问衰减判断 |
| 群聊未 @ | 未启用回复策略时只记上下文；启用后可以按策略主动接话 |
| 私聊 | 默认关闭；开启后自动回复 |
| 白名单外的群 | 完全不处理，不写库 |

群白名单 `BOT_GROUP_ALLOWLIST` 是硬边界。每个群一条串行处理通道，跨群并行；
积压有上限，满了**计数丢弃**而不是无限堆积。

### 长期记忆

每 N 条用户消息触发一次提炼：模型从最近对话里抽取可长期保留的事实，程序校验后
入库。回复时按当前消息检索相关记忆注入动态后缀。

**四步都存在**：数据模型、提炼去重分离、混合检索、生命周期。

- **数据模型**：事实类型、主体用户、来源事件、置信度、重要度、可见范围
  （`group` 群共享 / `personal` 仅本人）、有效期、状态。
- **去重与冲突**：写入是幂等的。同一事实再次出现会**强化**而不是新增；措辞不同
  的改写会合并；互相矛盾的会取代旧的那条。低置信度的先成为候选，反复出现才转正。
- **检索**：中文按字符二元组切分做词法匹配，可选叠加向量检索。
- **生命周期**：过期、归档、访问强化、显式遗忘。

**中文检索**是这个模块最容易做错的地方。SQLite 的 FTS5 需要正确分词，而中文没有
空格；`trigram` 分词器能救大部分场景，但**两字词**（备考、考试、喜欢）进不去索引。
所以子串降级路径承担了大多数真实查询，它必须是宽松的（OR + 按命中词数排序），
不能要求一条短句里出现提问的每个词。这一点有专门的回归测试。

配置：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BOT_MEMORY_EXTRACT_EVERY` | 8 | 每多少条用户消息提炼一次 |
| `BOT_MEMORY_EMBEDDING_PROVIDER` | 空 | 空 = 纯词法检索；`hash` 本地测试用；`openai` 走兼容接口 |
| `BOT_MEMORY_EMBEDDING_BASE_URL` / `_API_KEY` / `_MODEL` / `_DIM` | — | 向量服务配置 |

**向量不可用时自动退回词法检索，不影响启动。**

#### 实体与关系（三元组图，默认关闭）

事实回答「我知道小明的什么」，三元组回答「小明和那个项目是什么关系」——后者是
任何一条单行事实都答不了的。

开启后每段新对话多跑两次模型调用：第一次抽出**实体**，第二次把这份实体列表
交给模型、要它给出 `[主语, 关系, 宾语]`。**把这个列表递给第二次调用正是关键**——
它挡住了模型在没人提过的东西之间凭空联想关系。三元组至少得包含列表里的一个实体，
否则丢弃。

**默认关，而且目前没有消费者**：它只记录，还没有任何东西把结果读进提示词。这是
有意的顺序——先有存储和真实数据，再决定值不值得接进上下文，比起反过来的代价低得多。
参照实现的知识图谱是默认开的，结果它的缓存在单群涨到几百 MB、冷加载比注入超时还长，
每个群都静默丢了上下文。

**它不会为了记一条而毁掉另一条。** 同一主语和关系下出现不同宾语时，两条都留着，
`conflicts_for` 把它们作为**候选**报出来——是候选而非定论，因为「参与了项目」和
「参与了实验室」完全可以同时为真。关系不同（`喜欢 咖啡` / `讨厌 咖啡`）根本不算竞争。
谁对谁错不是存储层能独自决定的事，而它要删的那一行不可恢复。

配置：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BOT_MEMORY_GRAPH_ENABLED` | `false` | 关时一次调用都不发 |
| `BOT_MEMORY_GRAPH_MAX_ENTITIES` / `_MAX_TRIPLES` | 20 / 30 | 单段上限 |

### 群友档案与好感度

- **档案**：全局昵称 + **按群**的群名片（同一个人在不同群可以叫不同的名字）。
- **好感度**：按 `群 + 人` 独立，范围 -100..100，每人每群一小时冷却。
- **关系阶段**：好感度在提示词里**以阶段叙述出现，不是数字**——「关系阶段：普通
  群友。礼貌、简洁、就事论事，不主动搭话。」裸数字会诱使模型去推理那个数，而不是
  语气。
- **写入分层**：模型只能**提议**（`好感度 +1，原因是……`），由程序限幅、去重、
  冷却、按日限额后才落库。提议和拒绝都留审计记录。

**群消息不能直接改好感度**：让模型"把好感度改成 100"是无效的，有测试钉住这点。

`BOT_AFFECTION_AUTO_ENABLED=false` 可关闭自动评分，档案仍然可读。

**长期不互动会回落**（默认**关闭**）。设 `BOT_AFFECTION_DECAY_HALF_LIFE_SECONDS`
后，一段关系在静默 14 天后开始向中性移动，每半个半衰期减半。衰减以「上次真实互动」
为锚点，**不会因为扫描跑得勤而多衰减**——这是靠一个独立的 `decayed_at` 时间戳做到的，
因为把衰减记在 `updated_at` 上会让它看着像一次互动。

衰减**只在关系阶段真的变化时留审计**（阶段内的小幅漂移静默应用，因为它不改变 Bot 的
说法），而且这条审计记的是 `status='decayed'`，**不算作一次互动**：不会占掉冷却和每日
限额，也不会盖掉 `last_reason`。默认关闭的理由是——分数自己往下走会改变 Bot 对一个
什么都没做的人的态度，这该由部署者决定，不该是默认行为。

### 定时任务

在 `config/schedules.json` 定义 `at` / `every` / 五段 `cron`：

```json
{"jobs": [{"id": "water-noon", "group_id": "123456789",
           "kind": "cron", "value": "30 12 * * *",
           "prompt": "午休时间，结合最近群里的聊天随口接一句"}]}
```

`prompt` 是**给模型看的场景指令**，不是要发出去的原话。

- 任务类型走注册表，调度路径上没有 `if action == ...`；新增一种只需在扩展包里写一个
  handler 并在 `JOB_EXTENSIONS` 里登记。
- handler 自带的建议任务**默认停用**，所以丢文件绝不会自己开始发东西。
- 配额、冷却、群冷清是分开的闸门，互相不挤占。
- 错过的执行**不重放**：一次性任务永不补发；周期性任务在 5 分钟宽限内算「迟到」
  照常执行一次，超过宽限则整段跳过（记为 skipped 并写明错过了几次）——半夜
  补发十条午饭通知比不补更糟。
- **群成员不能创建、修改或关闭任务**，只有维护者通过本地配置或带认证的 WebUI 可以。

#### 两种主动说话的策略

它们是**不同的 action**，因为回答的是不同的问题：

| action | 触发条件 | 闸门 |
|---|---|---|
| `chat` | 部署者选定的固定时刻（`cron`） | 每日额度、冷却、群冷清、去重/字数。**不受心情门控** |
| `continuation` | 群里安静了一段时间（`every` 轮询 + 持久化的"静默窗口"） | 上面全部，外加心情门控与每群策略 |

`continuation` 就是 AIReplay 式的"最后一条消息之后 X 分钟"工作流，不是到点掷骰子：

1. **计时**：窗口由会话表里最新一条群友消息定义，不另存一份时间戳——不会漂移。
2. **判断**：安静满 `BOT_PROACTIVE_QUIET_MINUTES` 后才进入评估；先过部署级闸门
   （白名单、活跃时段、每群免打扰），再过窗口闸门（历史条数、是否还在聊、窗口是否
   已答过、是否已经太陈旧），最后才是当次决策（心情、日额度、发言冷却、概率）。
3. **当次沉默决策**：概率过了也不等于要发。模型仍可回答"没有合适的内容"，或者
   产出的句子太长、和最近重复——任何一条都记为 `skipped`，不发。
4. **重置**：说过一句（或判定窗口陈旧）后窗口关闭，直到**群里再次有人说话**才会
   重开——Bot 不会在冷场里自说自话。
5. **放弃**：静默超过 `BOT_PROACTIVE_FRESHNESS_MINUTES` 就丢弃这个窗口；连续沉默
   决策会拉长下一次尝试的间隔（上限即新鲜度窗口）。

两块状态落在主库的 `continuation_state` / `continuation_decisions` 两张表里
（`qunbot/storage/continuation.py`），所以**重启之后窗口、尝试记录和沉默次数都还在**。
每条决策都带原因留痕，`--check` 与调度器的 `job_runs.detail` 里都能看到"为什么这次
没说话"。

**每群细粒度策略**在本地文件里（默认 `./config/proactive_groups.json`，缺失就全用
环境变量默认值），可以给单个群设置免打扰时段、静默门槛、冷却、概率、日额度，或者
直接 `"enabled": false` 静音。模板见
`qunbot/extensions/scheduled_chat/data/proactive_groups.example.json`。
**这个文件只能由部署者改**，群成员既不能让 Bot 闭嘴，也不能让它多说话。

| 变量 | 默认 | 说明 |
|---|---|---|
| `BOT_PROACTIVE_ENABLED` | `true` | 整个 interval 续聊的开关 |
| `BOT_PROACTIVE_QUIET_MINUTES` | 12 | 需要安静多久 |
| `BOT_PROACTIVE_FRESHNESS_MINUTES` | 180 | 超过多久就丢弃窗口 |
| `BOT_PROACTIVE_RETRY_MINUTES` | 30 | 同一窗口内两次尝试的最小间隔 |
| `BOT_PROACTIVE_PROBABILITY` | 0.15 | 闸门全过之后开口的概率 |
| `BOT_PROACTIVE_INTERVAL_MINUTES` | 180 | 两次主动发言之间的最小间隔 |
| `BOT_PROACTIVE_DAILY_LIMIT` | 2 | 每日额度（与 `chat`/`poster` 各自独立） |
| `BOT_PROACTIVE_MIN_MESSAGES` / `_MAX_CHARS` | 3 / 150 | 上下文最少几条、单句最长多少字 |
| `BOT_PROACTIVE_QUIET_START_HOUR` / `_END_HOUR` | 23 / 8 | 全局免打扰时段（可跨零点） |
| `BOT_PROACTIVE_CHECK_SECONDS` | 300 | 多久评估一次（调度器 `every` 下限 300 秒） |
| `BOT_PROACTIVE_GROUPS_PATH` | `./config/proactive_groups.json` | 每群策略文件 |

两条触发路径（后台 `proactive_chat` worker 与调度器 `continuation` 任务）**共用同一份
配置和同一份持久化窗口**，所以同时启用也不会重复发言。

### Skill

`skills/*/SKILL.md` 是按需加载的指令，命中触发词才把全文放进这一轮。
**Skill 是提示说明，不是插件**——它不能执行代码、不能访问数据库。
只有启用了对应扩展，它的 Skill 才会出现在稳定前缀的目录里。

## 三、可选扩展

每个扩展都要**两件事同时满足**才生效：名字写进 `BOT_EXTENSIONS`，且它自己的
`BOT_*_ENABLED=true`。全部默认关闭。

```
BOT_EXTENSIONS=scheduled_chat,exam_poster,memes,mood,persona,reply_policy,slang,style_echo,world_context
```

### 核心基础设施

| 扩展 | 作用 |
|---|---|
| `scheduled_chat` | 提供 `chat`（定时水群）与 `continuation`（消息后间隔续聊）两个任务动作 |
| `exam_poster` | 提供 `poster` 任务动作（考研倒计时海报，Pillow 本地绘制，模型挂了也照发） |
| `proactive_chat` | 上面那个 interval 续聊的**后台 tick 版**：不写 `schedules.json` 也能跑 |

### `mood` — 机器人自己的心情

五个维度（心情/精力/压力/兴致/社交意愿）会随互动起落，并按半衰期自然回落到中性
基准。提示词里只给**自然语言心境**，不下发数值。心情差到一定程度时不会主动水群，
但**定时任务不受影响**，也绝不会因此失礼或迁怒。

状态存在独立的 `data/emotion.sqlite3`。

| 变量 | 默认 |
|---|---|
| `BOT_MOOD_ENABLED` | `true` |
| `BOT_MOOD_AUTO_ENABLED` | `true` |
| `BOT_MOOD_DECAY_MINUTES` | 180 |
| `BOT_MOOD_SENSITIVITY` | 1.0 |
| `BOT_MOOD_PROACTIVE_MIN_SOCIABILITY` | 35 |

### `persona` — 每轮的临时性格

在已有状态和本轮情境之上，生成**一句关于表达方式的有界指引**（例如：这会儿话短
一点）。三十分钟自动过期，回落到基线人格。

它**不拥有任何状态**——不是第二份情绪，只是从心情和情境派生出的措辞微调。这也
决定了优先级：预算紧张时先丢它，因为措辞可以重新推导，心情不行。

表达空间是一个**闭集词汇表**，模型返回的自由文本永远不会进入提示词。这让「群成员
无法通过聊天改人格」成为结构性保证，而不是一句约定。代价是表达空间比参考实现窄。

| 变量 | 默认 |
|---|---|
| `BOT_PERSONA_ENABLED` | `false` |
| `BOT_PERSONA_TTL_MINUTES` | 30 |

**绝不覆盖 `config/persona.md`**，有测试断言开关这个扩展前后稳定前缀逐字节相同。

#### 人设建议队列（默认关闭）

定期让模型读一遍最近的群聊，看看人设缺了什么，把答案排进一张表供 deployer 查看。
**它不写任何人设文件、不接任何提示词、批准也不改变运行时行为**——认可哪条，deployer
自己把它写进 `config/persona.md`。

这条界线是设计而非雏形。人设文件是**稳定前缀的开头**，前缀逐轮字节不变是有测试钉死
的；让模型的建议自己流进去，就等于把「群成员打了什么字」变成通往「Bot 是什么」的通道，
而那正是 `persona` 包存在的全部理由要挡的事。人读一句话、自己决定要不要敲进去，
这个通道就是关着的，代价只有一行代码。

它要的也是一句**命令式、口语化**的建议（「你应该多说点方言」「少说点感叹号」），
而不是让模型重写整份人设。参照实现让人设每次重写整篇，既贵又没法审，还得配上一整套
守卫（最小长度、缩水预算、前缀去重）才不至于把文件改坏。一句能一眼判断的话不需要这些。

去重要点：同一条建议不会重复排队——deployer 拒绝过的东西不该每六小时再问一次。

| 变量 | 默认 |
|---|---|
| `BOT_PERSONA_PROPOSALS_ENABLED` | `false` |
| `BOT_PERSONA_AUTO_EXAMPLES_ENABLED` | `false`：开启后只轮换固定人设文件中有标记的真实短对话示例，不改身份和边界；每次留备份 |
| `BOT_PERSONA_PROPOSAL_INTERVAL_HOURS` | 6 |
| `BOT_PERSONA_PROPOSAL_MIN_MESSAGES` | 20 |
| `BOT_PERSONA_PROPOSAL_WINDOW_MESSAGES` | 60 |

界面在「记忆中心 → 人设建议」。

### `reply_policy` — 回复决策

默认规则是「群聊只有被 @ 才回复」。这个扩展把它换成可替换的策略，能主动**弃权**
（不该说话时就沉默）。

`room` 模式读空气：Bot 刚说完话不接话头、刷屏不插嘴、多人对聊不打断、@ 别人才
沉默，但有人追问时会接上。

离线回放（28 例合成语料，含对抗性探针）：

| 模式 | 误回复率 | 漏回复率 | 准确率 |
|---|---|---|---|
| `mention_only`（默认） | 0/19 | 5/9 | 82.1% |
| `room` | 1/19 | 0/9 | 96.4% |

**这些数字是上限，不是真实群表现**——语料和启发式是同一批写的。回放框架本身是
可信的，用来在改动策略后看误回复率有没有变差。

| 变量 | 默认 | 说明 |
|---|---|---|
| `BOT_REPLY_POLICY_ENABLED` | `false` | 关 = 旧行为 |
| `BOT_REPLY_POLICY_MODE` | `mention_only` | `mention_only` / `room` |
| `BOT_REPLY_POLICY_THRESHOLD` | 0.5 | 越高越安静 |
| `BOT_REPLY_POLICY_COOLDOWN_SECONDS` | 20 | 刚说完话后不接话头 |
| `BOT_REPLY_POLICY_BOT_NAMES` | 空 | 正文里点名 Bot 的说法；空 = 该信号不生效 |
| `BOT_REPLY_POLICY_MENTION_PROBABILITY` | 0.85 | 被 @ 或点名后的基础回复概率 |
| `BOT_REPLY_POLICY_AMBIENT_PROBABILITY` | 0.25 | 未点名但读空气命中后的基础接话概率 |
| `BOT_REPLY_POLICY_DAILY_GROUP_LIMIT` | 20 | 每群每天最多成功接话次数 |
| `BOT_REPLY_POLICY_DAILY_USER_LIMIT` | 6 | 对同一用户每天最多成功接话次数 |
| `BOT_REPLY_POLICY_DECAY_HALF_LIFE_SECONDS` | 900 | 追问压力的半衰期；默认 15 分钟 |
| `BOT_REPLY_POLICY_DECAY_STRENGTH` | 0.45 | 连续消息对回复概率的指数压制强度 |
| `BOT_REPLY_POLICY_REPEAT_MULTIPLIER` | 0.20 | 高相似重复问题的额外概率乘数 |

### `slang` — 群内黑话

从群消息里发现这个群特有的说法，**搞清它在这里是什么意思**，再按需注入。
五步，边界就是特性：

1. **发现** — 统计群里反复出现、通用词表里没有的片段（`mining`，不调模型）
2. **打分** — 频次/人数/天数 → 0..1 置信度；久不用的会衰减
3. **推断释义** — 问模型两次再比较（`gloss`）：**一个词脱离上下文也能定义出来，
   那就不是黑话**。按批调用，不按词
4. **审查** — deployer 编辑 `config/slang_review.json`
5. **使用** — 低信任上下文，**只注入当前这句话里真的出现的词**

**关键：释义是全部价值。** 「本群特有说法：上大分」对模型毫无信息量——它本来就
认识常见词，而生造词是什么意思完全没说。所以**没有释义的词永远不会被注入**，
不管有没有被批准。deployer 想让它生效，就在审查文件里写下释义。

**注入按当前消息相关性匹配**：拿群友这句话去匹配词库，只注入命中的。
ASCII 词带词边界（`abc` 不会匹配 `xabcx`）。

**听得懂** ≠ **学得像**：模仿要更严格的条件（已审查 + 置信度达标 + 总开关打开）。
默认两者都不开。

置信度 = `0.5×频次 + 0.3×人数 + 0.2×天数`；**未审查的词**低于
`BOT_SLANG_MIN_OCCURRENCES` 次不会被注入，久不用的按半衰期衰减。
单次出现会落库（否则「每轮只出现一次」的词永远累积不起来），但不会被注入。

**成本是有界的，而且这里没有别的东西兜底**：默认部署的模型客户端**没有全局预算**，
所以唯一的开销上限就是这几个闸门——跨过 3 次出现前完全不调用模型；每群每
`BOT_SLANG_GLOSS_INTERVAL_SECONDS` 秒最多一轮；每轮最多
`BOT_SLANG_GLOSS_MAX_PER_SCAN` 个词。模型调用失败也照记一次尝试，否则配错 key
会变成每轮扫描一次调用。

**审查只走本地文件**，没有任何聊天命令，也没有注册工具——模型不能给自己批准词汇。
文件写坏了会保留上一次的好决策并大声记日志，不会静默清空。
文件里的 `meanings` 写下的释义记为「人工」，**后续推断不会覆盖它**；写 `null`
则解除覆盖、交还给自动推断。

| 变量 | 默认 |
|---|---|
| `BOT_SLANG_ENABLED` | `false` |
| `BOT_SLANG_STORE_OCCURRENCES` / `_MIN_OCCURRENCES` | 1 / 2（存储门槛 / 晋级门槛） |
| `BOT_SLANG_GLOSS_ENABLED` | `true`（无模型时自动降级为纯统计） |
| `BOT_SLANG_GLOSS_INTERVAL_SECONDS` / `_GLOSS_BATCH` / `_GLOSS_MAX_PER_SCAN` | 3600 / 12 / 24 |
| `BOT_SLANG_INFER_THRESHOLDS` | `3,6,10,20,40,60,100` |
| `BOT_SLANG_OVERWRITE_HUMAN_MEANINGS` | `false` |
| `BOT_SLANG_UNDERSTAND_CONFIDENCE` / `_IMITATE_CONFIDENCE` | 0.5 / 0.75 |
| `BOT_SLANG_ALLOW_UNREVIEWED` / `_ALLOW_IMITATION` | `false` / `false` |
| `BOT_SLANG_REVIEW_PATH` | `./config/slang_review.json` |
| `BOT_SLANG_WORDLIST_PATH` | 空（挂真实词典用） |

模板见 `qunbot/extensions/slang/data/slang_review.example.json`。

### `world_context` — 时间 / 天气 / 记忆回放

三个**可分别禁用**的提供者：

| 提供者 | 信任级别 | 说明 |
|---|---|---|
| `world_time` | `high` | 本机时钟，格式固定，没有第三方字节进入 |
| `world_weather` | `low` | 第三方 HTTP，可含任意文本（含错误页 HTML），被扁平化成一行 |
| `memory_replay` | `medium` | 经记忆端口只读回放，不建表、不复制记忆所有权 |

天气**未配置密钥时不创建客户端、不发任何请求**。关闭的提供者其子模块根本不会被
导入。

| 变量 | 默认 |
|---|---|
| `BOT_WORLD_TIME_ENABLED` / `_WEATHER_ENABLED` / `_REPLAY_ENABLED` | 全 `false` |
| `BOT_WORLD_TIMEZONE` | 空 → 回退 `BOT_TIMEZONE` |
| `BOT_WORLD_WEATHER_BASE_URL` / `_API_KEY` / `_CITY` | OpenWeatherMap 风格 |
| `BOT_WORLD_WEATHER_REFRESH_MINUTES` / `_TIMEOUT_SECONDS` | 30 / 5.0 |
| `BOT_WORLD_REPLAY_LIMIT` | 3 |

### `style_echo` — 表达风格

学习**部署者显式指定的**用户的表达方式。**默认不采集任何人**——需要把用户 ID 写进
`BOT_STYLE_ECHO_ALLOWED_USERS`；不在名单里的一条样本都不存。

「不冒充具体群友」是**代码约束**而不是意图：

- 风格画像里不含原文，只有句长分档、标点习惯、语气词（取自固定集合）等统计量。
- 渲染函数只接受画像对象，**不接受昵称或用户 ID**——按签名就不可能点名。
- 输出前过一次 fail-closed 校验：含「扮演/冒充/假装/你是」等词，或含**任何数字**，
  就拒绝发出。
- 指引只给**当前这位被采集的发言人**，不投射到与其他人对话里。
- 完整删除：`forget(user_id)` / `forget_scope` / `forget_all`。

| 变量 | 默认 |
|---|---|
| `BOT_STYLE_ECHO_ENABLED` | `false` |
| `BOT_STYLE_ECHO_ALLOWED_USERS` | 空（谁都不采集） |
| `BOT_STYLE_ECHO_MIN_SAMPLES` / `_MAX_SAMPLES` | 5 / 40 |
| `BOT_STYLE_ECHO_RETENTION_DAYS` | 30 |

### `memes` — 表情包

本地素材目录按标签检索。模型只能在回复末尾放一个 `[[meme:标签]]` 标记，且标签必须
在部署者配置的目录里存在。

### `voice` — 语音

可选的 OpenAI 兼容、Qwen-TTS 或 CosyVoice 语音源。**关闭时不创建任何 HTTP 客户端。**
合成失败回退成文本，不会让整轮回复失败。

### 出站消息是结构化的

表情包、语音、@ 不是靠字符串替换实现的。回复先被解析成结构化的
`Text / Image / Voice / At` 部件再发送：

- 标记只允许出现在正文**末尾**，每种最多一个；重复或位置错误时**整段按字面文本
  保留**——宁可少发一个表情包，也不静默吞掉用户打的字。
- **@ 目标只能引用名册里的成员**（本轮的触发者，以及本条消息里被 @ 的人）。两者
  都是 OneBot 断言的事实，不是模型产出的字符串，模型无法借此拼出任意指令。

### 扩展机制：manifest 是唯一事实来源

`qunbot/extensions/manifest.py` 是一张声明式表，每个扩展登记名称、版本、最低契约
版本、依赖、以及**它贡献什么**（job action / context provider / observer / tool /
worker / closer / media / reply policy …）。

- **启动前校验**：未知名称、依赖缺失、契约版本过旧、两个扩展抢同一个 action，
  都在**导入任何一个扩展模块之前**报错，且指出是哪个扩展缺什么。
- **贡献守卫**：注册期间监视 host 的每个面，碰了 manifest 没声明的面就是启动错误。
  一个包的爆炸半径因此可以**从表上读出来**，而不是靠约定。
- **不经允许的代码不会运行**：没有 manifest 行的目录，即使放在 `qunbot/extensions/`
  下也永远不会被导入——有测试写了一个真实可导入的包来证明这一点。
- **统一关闭**：逆序执行所有清理，单个失败不拖累其余。

**工具权限**：扩展注册的工具必须声明权限。可授予的只有 `READ_MEMORY` /
`READ_CONVERSATION` / `SEND_MESSAGE`；`MODIFY_AFFECTION` / `MODIFY_PERSONA` /
`CREATE_JOB` / `NETWORK` / `FILESYSTEM` 是**硬拒绝**——没有任何环境变量或 manifest
字段能授予它们。此外还有每分钟调用配额（超限返回一句模型可读的拒绝语，不抛异常）
和一份有界的审计记录。

## 四、安全与隐私边界

这些是**结构性约束**，不是配置项。

| 边界 | 怎么保证的 |
|---|---|
| 群成员不能管理 Bot | 没有安装扩展、改人格、改好感度、建任务、读数据库的聊天命令或工具 |
| 工具不能越权 | 扩展工具必须声明权限；改好感度/改人格/建任务/网络/文件系统是硬拒绝，无开关可授 |
| 群消息不是指令 | 提示词标注信任级别；模型产出的自由文本不进入人格 |
| 好感度不可被命令 | 模型只能提议，程序校验后才写；有测试（发「把好感度改成100」无效） |
| 人格文件只读 | 所有扩展都不写 `config/persona.md`；有测试断言稳定前缀不变 |
| @ 不可越权 | 目标必须在平台断言的名册里 |
| 私人记忆不串群友 | 检索按发言人过滤，同群的其他人读不到（这是修过的一个真缺陷） |
| 删除权 | `forget_user` 按 schema 自动发现所有含 `user_id` 的表，新增表不会漏 |
| 禁用即零成本 | 不在允许名单的扩展，其模块根本不会被导入（有子进程测试） |

## 五、验证状态

如实说明，**不要把单测当成已在 QQ 验证**。

**有测试覆盖（742 个，全绿）**：全部模块的单元行为、故障与降级路径、禁用路径、
迁移兼容、隐私删除、并发与队列上界、缓存前缀不变式、配置漂移（代码读了但没写进
`.env.example` 会红）。

**未经真实环境验证**：

- **从未连接过 NapCat，从未往真实 QQ 群发过任何消息。** 所有测试用模拟 gateway。
- 图片 URL 的有效期与可达性、语音消息的实际格式兼容性、真实模型服务的工具调用
  与多模态行为，均未实测。
- `reply_policy` 的回放语料是自己写的合成数据，不代表真实群。
- `mood` / `affection` 的模型评分质量与抗操纵性，只在结构层面保证，没有真实群
  对抗验证。
- `persistent prompt cache` 的命中率**没有测过**——本地的模型代理是否真的缓存、
  返回的 `cached_tokens` 是否可信，都需要实测。日志里记录了前缀摘要和 usage，
  但没有这个字段就不能声称缓存改善了。

## 六、已知限制

- **`reply_policy` 的 `room` 模式是启发式，不调模型。** 端口是异步的正是为了将来
  换成模型策略。已知失效模式：句子里的「你」指群友而非 Bot 时可能误回复，已登记
  为回归网。
- **人设建议队列的「认可」不会自动生效**：它只记录 deployer 的决定，采纳 = 自己把
  那句话写进 `config/persona.md`。这是有意为之（见上），但它确实比参照实现多一步手工。
- **人设建议没有回滚**：因为没有任何东西被自动应用，也就没有东西需要回滚。参照实现的
  `revert` 只把队列状态改回 pending、**并不撤销已写入的人格**，真正的恢复只能靠快照——
  这个坑没有采纳。
- **`persona` 的表达空间比参考实现窄**（闭集词汇表换结构性保证），且增量滞后一轮：
  一段对话的第一轮用基线人格。
- **`world_context` 的记忆回放接口偏窄**：只有 `related(scope, query, limit)`，
  没有按时间线或按被谈及的人回放的接口。
- **`slang` 的候选提取仍是 n-gram + 手写停用表**，不是分词器，所以会有噪音成为
  候选——但噪音既不会被推断释义也不会被注入（未审查的词要跨过次数门槛，且注入要求
  有释义），代价是占表。已规划引入可选分词依赖来减少噪音。
  两次扫描之间新增消息超过窗口上限时中间部分会漏看。
- **`slang` 的释义推断会把群消息原句发给模型**（作为判断语境的证据）。这是这个包
  唯一外发数据的地方，开启前需自行确认合规。推理用的原句不会进入提示词，只有释义
  会——有测试锁住这一点。
- **被判定为「普通词」的术语会退出再推断**（`inference_stage` 直接跳到末位）。
  若它日后在本群变成黑话，需要 deployer 在审查文件里对它写 `null` 解除。
- **`slang` 释义推断的失败是静默降级**：模型不可用或回复畸形时该轮跳过，术语仍在
  累积证据，只是没有释义、因而不会被注入。
- **`style_echo` 的分析是确定性启发式**，不是训练出来的文体模型，比较粗糙。
- **长会话没有摘要**：历史按字符预算整条丢弃，最旧的先掉。没有做摘要压缩。
- **`memory_replay` 与 Agent 自身的相关记忆走同一个检索入口**，语义上略有重复。
- **实体/关系图没有消费者**：`slang` 之外，`BOT_MEMORY_GRAPH_ENABLED` 打开后只写不读，
  没有任何路径把三元组送进提示词。检索接口（`related_relations`）已实现并有测试，
  但接入上下文是一个尚未做的产品决定。
- **三元组的「候选矛盾」会有误报**：同主语同关系不同宾语就报，而这类情况常常是
  两条各自成立的事实。它是给人看的清单，不是判定。
- **`relationships` 的关系类型是有意缺失的**：本模块只有一个 bot↔用户的标量，
  没有采纳参照实现那套用户间关系分类法（父母子女/同事/队友），也没有隐私开关。
- **同步 SQLite**：数据库调用在事件循环线程上执行。单次是亚毫秒级，且每群串行
  天然限制了速率，但高并发下仍可能阻塞。
- **租约已实现但默认未启用**：单实例仍是无条件假设，`app.py` 不传 `instance_id`。
- **重复时段的 cron 不去重**：夏令时回拨那天的 `30 1 * * *` 会跑两次（两个确实是
  不同的时刻），靠日额度与冷却吸收，没有做「本地墙钟今天已跑过」的检查。
- **调度没有重试**：`job_runs.attempt` 字段留好了，但没有退避、没有最大尝试次数。
- **工具权限是硬拒绝而非默认拒绝**：`NETWORK`/`FILESYSTEM`/`MODIFY_*` 无法被任何
  开关授予，比 roadmap 的最低要求更严——但没有留出「部署者显式授权」的口子。
- **扩展 manifest 是集中的一张表**（`qunbot/extensions/manifest.py`），不是每个包各
  自声明——集中便于一眼看全，代价是新增扩展要改两处。

## 七、快速上手

```bash
# 1. 最小可跑：纯聊天，零扩展
BOT_ONEBOT_TOKEN=... BOT_GROUP_ALLOWLIST=你的群号 BOT_MODEL_API_KEY=... \
BOT_EXTENSIONS= .venv/bin/qunbot

# 2. 看当前配置解析成了什么（不连 NapCat）
.venv/bin/qunbot --check

# 3. 逐一开启，每次 --check 确认
BOT_EXTENSIONS=scheduled_chat,exam_poster,memes,mood,persona,reply_policy,slang,style_echo,world_context
```

`.env.example` 列出了**全部**配置项及其含义——代码里读的每一个变量都在里面，有
测试保证两边不会漂移。
