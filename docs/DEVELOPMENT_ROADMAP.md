# QunBot 当前进度与接手路线

更新时间：2026-10-15。源码是当前事实，目标设计见 [ARCHITECTURE_CURRENT.md](ARCHITECTURE_CURRENT.md)。

## 已完成

- NapCat/OneBot 反向 WebSocket、白名单、私聊开关、入站去重和每群有界 FIFO。
- 实际消息账本、部分发送回执、引用/@/图片/语音消息段和“成功后才记为我说过”。
- 动态短期窗口（消息数/时间/字符数）与 Grok 压缩；压缩只处理旧段、失败不丢账本，且改为回复后的后台维护。
- 长期记忆事实/主题/证据、候选与生命周期、混合检索、当前群和当前发言人过滤。
- 行为经验图谱作为只读建议；不把历史人物合并为在线群友，不把经验当权限。
- 情绪、逐群友好感度、黑话、风格样本、媒体 Planner、QQ 原生互动、群管理提案、定时任务和 WebUI。
- 固定内核工具与 Skill 声明校验；没有运行时工具注册或外部动态工具协议。
- 所有共享模型调用受 `BOT_MODEL_MAX_CONCURRENCY` 限制；每群回合锁和后台任务均有界。

## 行为经验图谱（2026-10-15 更新）

图谱的**接线是完整的**：`app.py` 把 `configured_behavior_experience()` 交给 Agent，
`Agent.build_messages` 把它渲染进动态后缀的 `行为经验` 块。它一直没生效的原因不是
没接上，而是**成本**：

| | 改动前 | 改动后 |
| --- | --- | --- |
| 每轮检索 | ~320 ms | 3–5 ms |
| 启动加载 | 110 ms | ~360 ms（含建索引） |
| 常驻内存 | 85 MB | ~137 MB（含倒排索引） |

改动前 `retrieve()` 每轮都把 2007 条案例的检索文本重新分词一遍，而 query 会拼上最近
8 条消息，所以实测 322 ms/轮。它同步跑在事件循环上，会阻塞**所有**群的消息处理——这才是
它一直以「不配置路径」的方式停用的真实原因。

`BehaviorGraphRetriever` 现在在加载时建一次倒排索引（`_build_index`）。已在验证集+测试集
全部 468 条用例上逐条比对优化前后输出：策略、动作、表达结构、分数、避免项、媒体倾向、
支撑案例数、证据案例**全部一致**，脚本见 `scripts/verify_retrieval_equivalence.py`。

同时补上了异常隔离：`CompiledBehaviorExperience.context_for` 与 Agent 调用点都不会因为
图谱在查询期出错而让整条回复失败。

**启用方式**：在 `.env` 里指向编译好的快照目录即可。

```dotenv
BOT_BEHAVIOR_GRAPH_PATH=data/private/derived/behavior-graph-compiled-final-20261014-v7
BOT_BEHAVIOR_CALIBRATION_PATH=data/private/derived/behavior-validation-final-20261014/calibration.json
```

**质量现状（务必先读）**：留出集上 `coverage@3` 达 99.6–100%，但 top-1 策略族与期望族
一致率只有 **20.7%（验证集）/ 32.9%（测试集）**。取得到东西，但选得不准。所以它应当先在
测试群开启、按固定回放集评估后再进正式群，而不是默认打开。

## 多群策略

`group:<id>` 是消息、短期上下文、长期记忆、图谱证据、情绪、关系、媒体和配额的隔离边界。
同一 QQ 号在多个群是不同的记忆主体；跨群只读共享无个人身份的公共行为经验和基础人格规则。
详见 [ARCHITECTURE_CURRENT.md](ARCHITECTURE_CURRENT.md)。

## 下一阶段

### P0：上线前必须完成

1. 两群回放测试：同一 QQ 号在 A/B 群的事实、关系、黑话、风格、引用、压缩快照互不可见。
2. 每群指标：队列深度、模型等待、调用/失败/超时、token、缓存命中、后台积压。
3. 后台任务公平轮转和每群令牌桶，避免热群占满维护槽位。
4. SQLite 单实例租约或部署文档中的“单进程唯一消费者”硬检查；多进程不能直接启动。
5. NapCat 真实联调：断线、重连、重复事件、成功回执、重启后不复读/不重复欢迎。

### P1：质量提升

- 用固定回放集评估接话连续性、无根据复读、跨群泄露和媒体决策。
- 继续优化稳定前缀与动态后缀：人设/工具/Skill 常驻，群消息/记忆/状态只放后缀。
- 提高行为图谱的选择精度：当前 top-1 策略族一致率只有 20.7%/32.9%。优先做三件事——
  给 13 个策略补 IDF 或加权（现在纯按重叠词数打分，高频 2 字词会淹没信号）、
  扩充过薄的骨架（2034 个案例只归纳出 9 个 Situation / 13 个 Strategy）、
  以及为图谱增加负例、反例和「不该用某策略」的场景，低质量经验不进入在线上下文。
- 将同步 SQLite 查询逐步移到有界执行器，避免高峰阻塞事件循环。

### P2：扩展

- Skill 只补充表达指导和使用策略；新增真实能力按内核代码、契约、迁移和回放测试发布。
- 任何跨群公共知识都必须经过脱敏、人工确认和明确的 `public` 标记；默认拒绝共享。
