# QQ 群聊 Agent 架构规格

当前版本以 [ARCHITECTURE_CURRENT.md](ARCHITECTURE_CURRENT.md) 为实施基线。

## 稳定内核

内核固定负责入站账本、群作用域、动态会话窗口、长期记忆、行为经验、情绪和关系、
Planner/Executor、文本与媒体发送、原生 QQ 互动、群管理提案、定时任务、审计和 WebUI。
这些能力由版本代码和内置适配器组成，Skill 只能补充对话技巧和使用建议。

模型不直接发送消息、不直接访问文件或网络，也不能通过群聊修改配置。所有操作先生成
候选，再由代码校验目标群、成员、权限、额度、幂等状态和平台回执。

## 固定工具面

`conversation_read`、`knowledge_search`、`knowledge_evidence`、`group_query`、
`media_catalog`、`vision_analyze`、`audio_transcribe`、`interaction_propose`、
`group_action_propose`、`skill_load` 是唯一模型工具。工具 schema 和本体类型没有运行时
注册入口；新增真实能力必须经过代码审查和版本发布。

## 记忆和图谱

在线记忆按 `group:<id>` 或 `private:<id>` 隔离。个人主体键包含 scope，因此同一个 QQ
号在不同群是两个记忆主体。消息、短期压缩、关系、好感度、情绪、黑话、风格样本、媒体
和图谱证据都不能跨群召回。跨群只共享不含个人身份的、部署者确认的公共行为经验和基础
人格规则。

行为图谱保存场景、策略、对话动作、表达模式、话题/黑话、媒体意图、互动案例和证据。
它是只读建议资料，不是权限表、执行代码或事实账本。当前群的动态状态仍由独立模块拥有。

## 回合顺序

```text
OneBot 入站
  -> 白名单/去重
  -> 当前群 FIFO lane
  -> 现场窗口 + 当前群记忆 + 行为经验
  -> 回复/互动 Planner
  -> 代码校验与分段发送
  -> 成功回执写入实际账本
  -> 后台压缩、情绪、关系和学习
```

短期压缩只在回复成功后后台运行；压缩失败保留原始账本。模型缓存只优化成本，不能成为
事实来源。

## 扩展原则

Skill 是唯一公开扩展入口：只读 Markdown 指令、版本、触发条件、内容预算和所需内置
能力。Skill 不得提供 Python 入口、数据库迁移、本体 schema、权限、密钥或任意外部连接。
没有实现的能力不能靠 Skill 假装存在。
