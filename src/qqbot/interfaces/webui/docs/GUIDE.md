# Kinna bot 操作手册

这份手册写给 Bot 的维护者。你可以按任务查找步骤，不需要先理解整个项目。

> 在 WebUI 中点击“保存更改”只会更新 `.env`。配置不会立即进入正在运行的进程。保存后先执行配置检查，再重启 Bot。

## 先学会三件事

### 保存并检查配置

1. 在左侧打开需要修改的栏目。
2. 修改字段后点击“保存更改”。
3. 在项目目录执行：

   ```bash
   set -a
   source .env
   set +a
   .venv/bin/qqbot --check
   ```

4. 命令输出 JSON 且没有错误时，再重启 Bot。

密码、Token 和 App Secret 不会显示原值。密码框留空表示保留现有值。

### 判断 Bot 是否启动成功

启动日志至少应出现下面两类信息：

```text
WebUI listening on http://127.0.0.1:6200
OneBot reverse WebSocket listening at ws://0.0.0.0:6199/ws
```

NapCat 连上以后还会出现：

```text
connection open
```

没有 `connection open` 时，先检查 NapCat 的 WebSocket 客户端，不要先改模型或回复策略。

### 安全地排查问题

排查时不要把 `.env`、API Key 或 Token 发到群里。需要查看配置时，只确认字段是否存在，不要复制密钥内容。

## 接入 NapCat 和模型

### 开始前

你需要：

- 已登录 QQ 的 NapCat；
- 一个 OpenAI 兼容的模型接口；
- 一个测试群号；
- NapCat 和 Bot 使用的同一份 OneBot Token。

### 配置 Bot

打开“连接与模型”，填写：

1. “模型 API 地址”：填写服务的 `/v1` 根地址。
2. “模型 API Key”：填写模型密钥。
3. “模型名称”：填写接口接受的模型名。
4. “OneBot 端口”：默认是 `6199`。
5. “OneBot Token”：生成一段独立的随机字符串。
6. “群白名单”：先只填测试群号。
7. 保持“允许私聊”关闭。

### 配置 NapCat

在 NapCat WebUI 中新建 WebSocket 客户端：

- URL：`ws://127.0.0.1:6199/ws`
- Token：与“连接与模型”中的 OneBot Token 相同
- 消息格式：数组

启用连接后，查看 Bot 日志。出现 `connection open` 表示 QQ 链路已建立。

### 验证

在白名单群里 @ Bot 并发送“你好”。验证下面三点：

1. Bot 日志收到群消息；
2. 模型接口返回成功；
3. QQ 群里收到回复。

如果只有前两步成功，检查 NapCat 是否允许发送群消息。如果第一步就失败，检查 URL、端口、Token 和 `/ws` 路径。

### 这些参数什么时候需要改

- **推理强度**：群聊优先使用 `low` 或留空。提高推理强度会增加延迟和成本。
- **OneBot 监听地址**：NapCat 与 Bot 在同一台机器时用 `127.0.0.1`。跨容器或跨机器部署才需要其他地址，并应同时限制防火墙来源。
- **群白名单**：只有列出的群会进入对话链路。新增群之前先确认该群允许 Bot 记录消息。
- **允许私聊**：开启后，私聊会进入会话、记忆和关系系统。没有发送者白名单时不建议开启。

### 实现说明

`src/qqbot/infrastructure/adapters/onebot.py` 接收 OneBot 事件并执行发送动作。`src/qqbot/infrastructure/adapters/events.py` 把原始事件转换为内部消息。`src/qqbot/infrastructure/adapters/model.py` 调用模型接口。它们都由 `src/qqbot/agent/service.py` 串联。

## 控制 Bot 什么时候回复

### 只在被 @ 时回复

打开“对话决策”：

1. 开启“启用读空气策略”。
2. 将“回复模式”设为 `mention_only`。
3. 保存、检查并重启。

此模式适合刚接入的新群。普通群聊只会写入上下文，不会主动插话。

### 允许 Bot 读空气接话

1. 将“回复模式”设为 `room`。
2. 把“回复阈值”设为 `0.50`。
3. 把“主动接话概率”设为 `0.15`。
4. 为测试群设置合理的每日群上限和每日用户上限。
5. 观察一天，再根据实际行为调整。

不要同时大幅降低阈值和提高主动概率。两个改动叠加后，Bot 很容易变成话痨。

### Bot 太吵

按下面顺序调整，每次只改一项：

1. 降低“主动接话概率”；
2. 提高“回复阈值”；
3. 降低“每群每日回复上限”；
4. 如果仍不合适，切回 `mention_only`。

### 被 @ 也不回复

被 @ 不代表一定调用模型。依次检查：

1. 该用户是否已经达到每日用户上限；
2. 群是否达到每日群上限；
3. 用户是否在短时间内反复追问，触发了衰退；
4. “被 @ 回复概率”是否过低；
5. 模型或发送链路是否报错。

不要直接把概率改成 `1` 来掩盖额度或连接问题。

### 参数关系

- **回复阈值**决定当前消息是否值得参与。值越高，Bot 越克制。
- **被 @ 回复概率**只在没有触发硬限制时生效。
- **主动接话概率**只控制没有 @ 的情况。
- **每日群上限**控制群的总成本。
- **每日用户上限**防止一个人持续消耗额度。
- **记忆提炼间隔**不是回复概率。值越小，记忆更新越快，但模型调用更多。

### 实现说明

`src/qqbot/agent/conversation/intelligence/` 用本地规则维护最近话题，不调用模型分析每条消息。`src/qqbot/features/reply_policy/` 在模型调用前检查评分、概率、额度和追问衰退。只有通过这些检查，`ConversationService` 才会构建提示词。

## 配置记忆、好感度和人格

### 开启长期记忆

长期记忆属于核心能力，不需要单独启用插件。你主要需要调整“每多少条消息提炼记忆”。

- 群消息较少：可以使用 `6` 到 `8`。
- 群消息很多：建议使用 `10` 到 `20`，避免频繁提炼。
- 只做链路测试：保持默认值，不要为了立刻看到记忆而设得过小。

记忆提炼失败不会阻止正常回复。先保证对话链路稳定，再单独排查记忆。

### 开启好感度

打开“记忆与人格”，开启“自动更新好感度”。Bot 会在回复后异步判断本次互动是否值得改变关系状态。

关闭该开关不会删除已有好感度，只会停止自动更新。

### 调整情绪持续时间

“情绪半衰期”表示状态向中性恢复的速度：

- `60` 到 `120` 分钟：情绪变化快，也恢复得快；
- `180` 分钟：适合日常群聊；
- 更长时间：状态更连续，但一次负面互动影响也更久。

情绪只能影响表达倾向和主动发言意愿，不能让 Bot 失礼或绕过管理规则。

### 学习群黑话

1. 开启“群黑话学习”。
2. 确认 `BOT_EXTENSIONS` 包含 `slang`，让 Bot 收集候选词并推断含义。
3. 高置信度且有释义的未审核词只可用于**理解**群友的话，不会被 Bot 说出口。
4. 在「记忆中心 → 黑话」里逐条审核：核对这个词在本群的意思，再点通过。
5. 开启“允许模仿已审核黑话”后，只有审核通过且达到模仿置信度的词才可自然使用。

**没有释义的词不会被注入。** 光有一个词对模型毫无信息量——它本来就认识常见词，
而生造词是什么意思你还没告诉它。所以那一步不能省；输入框下面会提示。

同一处的按钮直接改 `config/slang_review.json`，和你自己手改那个文件完全等价，
不会有第二份数据。你在界面上写的释义会被记为「人工」，**后续自动推断不会覆盖它**；
清空输入框保存就把它交还给自动推断，点「重置」则连状态一起退回候选。

不要直接允许 Bot 模仿未审核词语。群里可能出现针对个人的外号、攻击性表达或短期玩笑。

### 风格示例自动演进

1. 确认 `BOT_EXTENSIONS` 包含 `persona`，并开启“动态人格”“定期扫描对话风格”“自动演进风格示例”。
2. 扫描每 6 小时最多尝试一次，且需要至少 20 条新群消息；安静时不调用模型。
3. 系统从实际发出、相邻的群友—Bot 短对话中找候选。代码先剔除复读、过长、事实断言、链接、数字串和疑似指令；模型结合现场与固定人设只选候选编号，也可以不选，不能生成新台词。写入人设时，群友原话改成程序定义的场景提示，避免把群友文本升级为系统指令。
4. 选中后只更新 `config/persona.md` 中 `persona-examples:start/end` 之间的示例；最多保留 8 个，旧版保存到 `config/persona-history/`。下一轮回复会加载新文件，不需重启。记忆中心保留采纳记录。

**身份、专业操守、边界和群聊定位不会自动改。** 自动演进只调整示例窗口，不把群友的要求当指令。筛选并不能保证每个例子都好；发现风格变差时，从 `persona-history/` 取回旧文件，或关闭“自动演进风格示例”。恢复后下轮回复即生效。人设文件变化会使模型前缀缓存重新建立一次，因此更新频率受到时间和消息量双重限制。

### 学习群聊的表达节奏

1. 开启“语言风格学习”，并确认 `BOT_EXTENSIONS` 包含 `style_echo`。
2. 将“指定用户风格采样名单”留空，使用群体模式。
3. 至少三名群友有足够的近期正常发言后，模块会提取句长、语气词等统计特征。

群体模式只读取已有的对话账本，计算短期统计提示；它不另存群友原话，不把任何人的句子
交给模型照搬，也不会改变稳定人格。较长的讲解和密集问句不会变成 Bot 的日常习惯。

如果确实需要研究某个已同意的群友的个人写作习惯，可以填写其 QQ 号；这会切换到
逐人采样模式，只采集名单内用户，多个 QQ 号用英文逗号分隔。

### 修改稳定人格

WebUI 中的“动态人格”只控制每轮的临时表达偏移。要修改稳定人设，请编辑：

```text
config/persona.md
```

稳定人格不要混入实时情绪、群友档案或最近话题。这些内容变化频繁，会破坏提示词前缀缓存。

### 实现说明

`src/qqbot/agent/memory/` 负责提炼、去重和召回。`src/qqbot/agent/memory/relationships/` 保存每位群友的关系状态。`src/qqbot/agent/identity/emotion/` 保存 Bot 自身状态并按时间衰退。Persona、Slang 和 Style Echo 只通过有长度限制的动态上下文进入当前回复。

## 配置主动发言和定时任务

### 先分清两种行为

- **主动接话**：群安静一段时间后，Bot 判断是否自然地续聊。它受概率、额度、话题新鲜度、免打扰和情绪影响。
- **定时任务**：到指定时间执行。固定送达任务不应因为群里不活跃而取消。

### 开启主动接话

打开“主动发言”：

1. 开启“启用主动接话”。
2. 将“主动接话概率”设为 `0.10` 到 `0.15`。
3. 将“每日主动发言上限”设为 `1` 或 `2`。
4. 将“群沉默多久后接话”设为 `12` 到 `20` 分钟。
5. 设置免打扰时间，例如 `23` 到 `8`。
6. 保存、检查并重启。

概率只在其他检查全部通过后抽样，不是每条群消息都抽一次。

### Bot 总在旧话题上接话

降低“话题最长保鲜时间”。如果群聊节奏很快，可以从 `180` 分钟降到 `60` 分钟。不要通过无限增加历史消息来解决，这会增加成本并降低话题准确性。

### 新增一次性测试任务

打开侧边栏的“任务中心”，点击“新建任务”：

1. 调度类型选择“单次执行”；
2. 调度值填写带时区的未来时间，例如 `2026-09-24T20:00:00+08:00`；
3. 执行动作选择 `deliver`；
4. Prompt 可填写这次任务的用途；
5. 动作参数填写下面的 JSON；
6. 保存后，任务立即同步到调度器，不需要重启 Bot。

```json
{
  "text": "定时任务测试成功",
  "channels": ["text"]
}
```

把时间改为未来时间，并把群号改为白名单群。`deliver` 直接发送 `payload`，适合验证调度和发送链路，不会先调用模型生成内容。

### 新增每天执行的任务

在“任务中心”中新建任务，调度类型选择 `Cron`，调度值填写 `35 17 * * *`，执行动作选择 `chat`，Prompt 填写“晚饭时间到了，结合今天群里的聊天自然说一句话。”。表单下方会预览接下来三次执行时间，确认时区和时间后再保存。

任务列表可以停用、编辑、删除或立即执行任务。“立即执行”会创建一条独立的手动运行记录，不会改变任务原来的下次执行时间。时间线只展示当前等待执行的任务，运行记录则保留成功、跳过、失败和超时原因。

任务模板来自已启用的扩展，默认不会执行。需要使用时进入“任务模板”，选择模板后补充目标群和参数，再保存为管理员任务。

### 任务没有执行

依次检查：

1. 群号是否在白名单；
2. 时区是否为 `Asia/Shanghai`；
3. 时间是否仍在未来；
4. JSON 是否有效；
5. 动作名称是否存在；
6. 是否超出全局活跃时段；
7. 在“运行记录”中查看任务是失败、跳过还是超时。

### 实现说明

`src/qqbot/actions/scheduling/management.py` 是任务中心的应用服务：它验证表单、原子写入 `config/schedules.json`，然后调用调度器同步数据库。WebUI 不直接修改任务表。`scheduled_chat` 注册 `chat`、`deliver` 和 `continuation` 动作，其他扩展也可以注册新的动作和模板。`proactive_chat` 是独立后台 worker，两者共用发送服务，但不共用触发规则。

## 使用群管理功能

### 开始前

Bot 使用的 QQ 号必须是目标群的管理员或群主。WebUI 中开启功能不能替代 QQ 权限。

在“管理操作授权人”中填写允许批准写操作的 QQ 号。名单为空时，Bot 仍可查询群文件和发送欢迎词，但聊天触发的禁言、精华等写操作会被拒绝。

### 设置禁言上限

“最长禁言秒数”限制单次禁言的最大时间。建议先设为 `600`。即使模型提出更长时间，服务端也会拒绝或限制。

### 开启入群审核

1. 开启“自动入群审核”。
2. 在 `.env` 中配置通过关键词和拒绝关键词。
3. 保持“无规则时默认通过”关闭。
4. 使用测试账号提交一次入群申请。
5. 检查命中规则、未命中规则和拒绝规则三种情况。

公共群不建议开启“无规则时默认通过”。未命中确定规则时保留人工审核更安全。

### 设置欢迎词

1. 开启“新人欢迎”。
2. 保存并重启。新成员入群时，模型会根据群聊语境和成员昵称生成简短欢迎词。
3. 用测试账号入群，检查实际欢迎内容。模型不可用时不会发送固定兜底文案；请查看日志排查。

### 使用群头衔提案

Bot 不能直接给人授予头衔。流程是：

1. Bot 提出头衔和候选人；
2. 候选人本人同意，或唯一群友票数达到门槛；
3. 提案仍在有效期内；
4. Bot 调用 NapCat 授予头衔。

“头衔投票门槛”至少应为 `2`。同一个人的重复投票只算一次。

### 管理动作失败

检查 Bot QQ 的群权限、授权人名单、目标成员身份和 NapCat 返回的错误。不要只看模型是否调用了工具；真正的权限检查发生在工具服务和 QQ 平台两层。

### 实现说明

`src/qqbot/features/qq_admin/` 实现群文件、禁言、精华、入群审核、欢迎和头衔提案。`src/qqbot/actions/tools/registry.py` 负责工具权限与调用频率。最终动作由 `OneBotGateway` 发给 NapCat。

## 配置表情包、语音和 QQ 频道

### QQ 原生轻互动

“消息贴表情”是在群友原消息下方添加 QQ 表情回应，不会额外发送一条消息。它由本地关键词和限流策略决定，不调用模型。`0.65` 表示命中明确语义后有 65% 概率执行，并不表示 65% 的全部群消息都会被点赞。群冷却控制连续操作间隔，每群和每人的每日上限用于避免 Bot 变成刷反应机器。

“引用回复”使用 OneBot 的 `reply` 消息段。模型只能提出它想承接的消息；本地代码只接受当前消息或当前消息已经引用的 ID，无法让模型构造任意消息 ID。引用的原文不在近期窗口时，Bot 会通过 NapCat `get_msg` 最多补取三层。图片按 URL 去重，只进入视觉上下文一次。

复读、骰子和猜拳不调用模型。两名不同群友连续发送同一句短文本后，Bot 才可能加入一次复读；链接、过长文本和疑似敏感数字串会被排除。骰子和猜拳需要明确 @ Bot，分别发送 QQ 原生 `dice` 和 `rps` 消息段。

戳一戳事件可以触发反戳、短回复、两者同时执行或保持沉默。连续戳受同一用户冷却和每日上限限制，因此不会形成互戳死循环。所有成功的复读、小游戏和戳一戳动作都会作为 Bot 的真实行为写回短期会话。

“拟人发送延迟”只延迟输出，不改变回复内容。延迟由基础值、回复长度和少量随机抖动组成，并受最大值限制；文字和语音同时发送时，中间还会保留一个短间隔。

### 使用表情包

1. 确认 `BOT_EXTENSIONS` 包含 `memes`。
2. “表情包目录”指向本地目录，默认是 `./memes`。
3. 在目录的 catalog 中维护文件与标签。
4. 重启后检查模型可见的媒体能力。

项目默认图库使用 AstrBot「官方表情包 1 号」的分类映射，并按中文标签索引素材；来源与非商业许可声明见 `memes/astrbot-official-01/SOURCE.md`。如需商业使用或公开再分发，请先核实素材权利。只需修改 `memes/catalog.json` 即可调整分类标签，无须改动发送代码。

回复规划器决定发送文字、表情包或两者。表情包不存在时，文字回复仍应正常发送。

闲聊短句语音概率只对群聊中的简短、适合朗读的文字生效：抽中后改为只发语音，不把同一句再发成文字。发言后表情包概率只在回复与本地图库标签语义匹配时生效；会先发文字，稍作间隔后再独立发图，不是把图片混在文字消息里。两个参数都是 0～1，设为 0 可关闭；图片素材缺失时不会强行发图。QQ 原生表情有自己的概率，和本地图片表情包是两条通道。

“随机斗图概率”是第三条独立路径：闲聊文字没有匹配到特定表情时，从轻松互动标签中随机选一张跟发。精确资料和严重求助不会随机配图。把它设为 0 就关闭；过高会显得刷屏，建议先用 0.2 观察。

### 开启阿里语音

1. 确认 `BOT_EXTENSIONS` 包含 `voice`。
2. “语音服务”选择 `dashscope`。
3. 填写语音 API Key、模型和模型支持的音色。
4. 保存、检查并重启。
5. 先在测试群发送一条固定短语音，确认合成和 QQ 发送都成功。

语音合成成功但 QQ 没有收到时，查看 NapCat 是否接受当前音频格式。模型正常回复但没有调用语音时，检查回复规划器是否把 voice 识别为已启用能力。

### 开启 QQ 官方频道

QQ 官方频道与普通 QQ 群是两套身份和 API。频道配置使用开放平台 App ID 和 App Secret，不使用 QQ 号密码。

1. 开启“启用 QQ 官方频道”。
2. 填写 App ID 和 App Secret。
3. 在“频道写操作授权人”中填写允许批准写操作的 QQ 号。
4. 保存并重启。
5. 先执行只读查询，确认 Bot 已加入目标频道并拥有权限。
6. 再测试发帖、评论或公告等写操作。

如果查询结果为空，先确认开放平台 Bot 是否真的加入了频道，不要根据普通 QQ 号的频道管理员身份推断开放平台 Bot 已有权限。

### 实现说明

`src/qqbot/actions/replies/` 负责通道规划和发送顺序。`memes`、`voice` 和 `qq_channel` 都是独立扩展；未启用时不会创建对应客户端。一个媒体通道失败时，发送器会尽量保留其他可用通道。

## 管理扩展和系统参数

### 启用或停用扩展

在“系统”的“启用扩展”中填写扩展名称，使用英文逗号分隔。名称必须存在于 `src/qqbot/features/manifest.py`。

停用扩展只是不再装配该能力，不会自动删除数据库、媒体文件或配置字段。

保存后必须运行：

```bash
.venv/bin/qqbot --check
```

出现 unknown extension、missing dependency 或 contribution 错误时，不要强行启动。先修正扩展名称或依赖。

### 什么时候调整队列

保持默认值，除非日志明确显示积压或丢弃：

- “观察队列容量”影响回复后的记忆、好感度和情绪观察任务；
- “群消息并发通道”影响可同时处理多少个群；
- 同一个群内部仍按顺序处理，增加通道不会让同一群并行回复。

盲目放大队列只会增加内存使用和停机等待时间。

### 备份数据库

数据库路径默认是：

```text
./data/qqbot.sqlite3
```

备份前先停止 Bot，避免复制到一半时数据库仍在写入。情绪扩展如果使用独立数据库，也要一起备份。

### 为什么群友不能修改配置

群消息只能触发明确注册的对话和工具能力。WebUI 配置 API 使用独立登录密钥，并且只接受 schema 中列出的字段。扩展也不会通过扫描目录自动加载，必须同时进入本地 manifest 和 `BOT_EXTENSIONS`。

### 实现说明

`src/qqbot/features/manifest.py` 是扩展允许名单。`loader.py` 校验依赖和贡献边界。`features.py` 定义扩展可以注册的宿主接口。`app.py` 是组合根，统一启动网关、调度器和后台 worker，并按逆序关闭资源。

## 常见问题

### 保存后为什么没有变化

WebUI 已经写入 `.env`，但运行中的进程仍使用启动时读取的配置。运行配置检查并重启 Bot。

### 为什么配置检查通过，实际功能仍失败

`--check` 能检查格式、扩展依赖和本地资源，但不能保证外部服务可用。模型 API、NapCat、阿里语音和 QQ 开放平台仍需要分别联调。

### 为什么 Bot 记得群里的内容，却不主动回复

记录上下文和决定回复是两条路径。消息可以进入会话和记忆，但被回复策略、额度、概率或免打扰拦截。

### 为什么定时任务没受群聊状态影响

这是预期行为。固定时间任务用于确定性执行；读取群状态后再决定是否发言，应使用主动接话或 continuation。

### 怎么降低模型成本

优先调整回复准入和主动发言，不要先删记忆：

1. 提高回复阈值；
2. 降低主动接话概率和每日额度；
3. 增大记忆提炼间隔；
4. 保持稳定人格和工具说明位于提示词前部；
5. 只在动态后缀注入当前话题、相关记忆和状态摘要。

### 每日私聊人数

在连接配置中开启“允许私聊”，并设置“每日私聊人数上限”（默认 10）。
按 Bot 时区的自然日统计不同 QQ 用户，同一人重复聊天不重复占名额，重启不会清空。
人数耗尽后，新用户不会进入模型、媒体理解或记忆提炼；设为 0 拒绝所有私聊准入。
群聊不受此名额影响。这个选项限制接待人数，不限制每人的消息条数或保证固定费用。


## 数据看板与运行追踪

新版首页提供运行总览、对话追踪、Wiki 关联、用量与缓存以及核心配置。原有任务、审核、实验与完整参数入口保留在 `/advanced`。控制台密钥仍然只供部署者使用，聊天用户没有记忆或内部策略开关。

运行追踪随 Bot 主进程装配，记录新版本接收的每条消息及其程序步骤；单独启动控制台不会连接运行数据库，也不会显示虚假的在线状态。消息的过滤、跳过、身份保护、生成失败和发送结果分别记录。此处的 Trace 是操作证据，不是模型内部思考，也不保存完整提示词、工具参数、模型回复或 API 密钥。通过事件 ID 可在原有消息存储中核对聊天。

每条追踪最多 128 个步骤，最多保留 30 天或 50,000 条；看板查询支持最近 1 小时、24 小时和 7 天，以及精确会话筛选。用量累计当前消息中的所有模型调用，包括身份保护与工具循环。后台提炼、定时与主动任务没有归入消息追踪，因此此页不是全账户账单。供应商未报告的 Token 保持未知，汇总只累计已知值，并展示缺失调用数。没有模型价格表时不估算金额。缓存命中率只用已报告的缓存读取 Token 除以对应样本的输入 Token，稳定前缀指纹不能视作缓存命中证据。

Wiki 图谱读取已装配 Wiki 读取器的 Markdown 发布目录，只展示实体和显式链接。支持搜索、缩放、平移、节点选择、最新事实、主题、黑话、人物关系、出链和反向链接；最多显示 200 个节点，超出时应缩小范围。知识图谱为另一只读视图，沿用既有可选图谱模块，未接入时不生成演示关联。Wiki 与知识图谱均不因打开页面而自动启用。

核心配置仅展示主要策略和少量成本边界；保存写入部署者的环境配置，重启 Bot 后生效。界面展示的保存值不能代表当前进程已经热切换。细节参数仍可通过完整配置维护。


## 运行看板的观测范围

运行看板沿用原控制台的导航和视觉样式，新增 Skill 与工具调用观测。Skill 频率来自每条 Trace 实际选中的 Skill 名称；同一条消息重复出现会按实际选择次数累计。工具频率来自工具执行边界，调用结果按完成、失败和未知分开统计。总览同时给出会话范围分布，便于发现某个群或私聊通道的工具异常集中。

这些计数只来自保留的运行 Trace，受时间范围、会话筛选、30 天和 50,000 条保留上限影响。没有记录的 Skill 或工具显示为空，不会用配置声明推算调用次数。


## 数据存储与定时任务

“数据存储”页读取运行 Bot 实际使用的 SQLite 数据库，展示真实表结构、字段、行数和有限行数据。SQL 区域只接受单条 SELECT，限制返回 200 行，拒绝多语句、写操作、系统表和非法表名。它是排查和核对工具，不替代业务写入边界；写入仍必须通过配置、审核、消息投影或任务管理接口完成。

“任务中心”沿用原工作台已有的定时任务接口：任务列表、启停和编辑、时间预览、立即运行、建议模板以及运行历史都从 `ScheduleManagementService` 读取或写入。控制台单独启动时这些运行时接口会显示“服务尚未就绪”，与真实 Bot 绑定后才会操作实际任务。


## Skill 管理

“Skill 管理”读的是 `skills/` 目录本身，不是运行中的 catalog。这点很重要：catalog 只包含被扩展白名单放进来的 Skill，如果页面建在 catalog 上，一个 Skill 停止生效时你只会看到它“消失了”，看不到原因。目录视图能直接回答“它还在，但没生效，因为它的扩展没开”。

每个 Skill 的状态只有四种，并且一定带原因：

- **启用中**：文件正常、没被本机停用、所属扩展也启用；
- **已停用**：在 `skills/.state.json` 的 `disabled` 列表里，运行时直接跳过；
- **扩展未启用**：文件正常，但不在 `BOT_EXTENSIONS` 算出来的白名单里；
- **有问题**：目录里没有 `SKILL.md`、frontmatter 不合法、缺 `description`，或者两个目录声明了同一个 `name`。

可以做的事：

- **新建**：填名称、描述、触发词、优先级、作用域和正文，写入 `skills/<名称>/SKILL.md`。名称只能是小写字母、数字、`-` 和 `_`。
- **导入**：选一个本地 `SKILL.md`，浏览器读出内容后提交，服务端原样写入，保留作者排版。名称取自 frontmatter 的 `name:`，没有就用文件名。
- **编辑**：改描述、触发词、优先级、作用域、常驻和正文。保存时重新生成规范的 frontmatter，写完后**立即重载目录**，不用重启。
- **启停**：写 `skills/.state.json`，同样立即重载。如果这个 Skill 的扩展本来就没开，页面会直接说“改开关不会让它生效”，不会假装成功。
- **归档**：目录移到 `skills/.archive/<名称>-<时间戳>`，不删除文件，可以手工搬回来。

两个容易踩的点，页面会主动提示：

1. 带 `bot-adapter.json` 的 Skill（比如 `goutoujunshi`、`private-chat`）实际生效的不是整个 `SKILL.md`，而是适配器挑出来的小节和 `body_file`，还有字数上限。编辑正文时如果删掉了被引用的小节标题，保存会被拒绝——否则改完看起来成功、运行时却什么都不剩。
2. `always_on` 写在 frontmatter 里是有效的（每轮都注入，不靠触发词）；带适配器的 Skill 以适配器为准。

Skill 仍然只是文本。控制台能写的位置就是加载器本来就会读的位置，没有引入任何执行入口。


## 线上监控

“线上监控”是给部署者看实时状态的页面，每 5 秒刷新一次，窗口可选 5、15 或 60 分钟。它不读取聊天内容，只读进程自己的计数和消息 Trace。

页面结构从上到下是：健康横幅 → 六个关键指标 → 吞吐曲线与会话分布 → 告警与网关状态 → 最近消息 → 进程日志。

健康结论只有三档：正常、降级、不可用，并且一定带原因。判断依据是真实信号：OneBot 连接是否存在、入站是否丢弃过帧、窗口内失败率是否超过 30%、P95 延迟是否超过 20 秒、模型名称与 API 地址是否都配置。任一信号没有接入时显示“未接入”或“未知”，不会用 0 伪装成正常。

吞吐曲线是每分钟消息数的折线，纵轴是真实峰值，红点表示那一分钟出现过失败轮次。图上没有任何数据时会直接写“这段时间没有消息”，而不是画一条贴底的假线。

“会话分布”按轮次排序，能看出是哪个群或私聊在吃处理能力；点“最近消息”表里的会话名，可以只看那一个会话，再点一次取消。

日志区可以按级别筛选、按内容或来源搜索。日志是内存环形缓冲，最多 500 条，只收 WARNING 及以上，不写磁盘，重启即清空。

右上角“暂停”会停掉轮询但保留当前画面，适合截图或对照时间点；“刷新”是手动拉一次。

排查顺序建议：

1. 先看 OneBot 是否已连接。掉线时入站消息全部丢失，其他指标都没有意义。
2. 再看“入站丢弃”。出现丢弃说明队列或并发通道被打满，先看“群消息并发通道”和队列容量。
3. 然后看失败率与 P95。失败率只统计窗口内已结束的轮次，不含仍在处理的请求。
4. 最后看进程日志。

“最后一条消息”超过 30 分钟只给提示级告警：群里可能确实没人说话，需要结合 OneBot 状态判断，不能直接判定掉线。

## 工具调用

“工具调用”按终态统计，不按步骤统计。一次工具调用会写两条 Trace（开始和结束），如果按步骤计数会翻倍，所以这里只数结束那一条；只有开始、没有结束的调用单独显示为“在途未结束”。

页面提供按时间范围（1 小时、24 小时、7 天）和按工具的筛选。点表格里的一行即可只看该工具的调用明细。结果分三类：完成、失败、未知；未知不会被算进成功率。

工具步本身不记录耗时，因此明细里的“工具耗时”显示“未记录”，不会借用整轮耗时冒充。整轮耗时请看“运行看板”。

## 链路与图谱

“链路与图谱”回答两个问题：这一轮消息经过哪些环节，以及当前用的是哪条模型和图谱路线。

链路条按运行时顺序展示：准入、记忆、行为路由、模型、工具、投递。灰色表示该环节当前关闭，判断依据是 `.env` 里的真实开关，不是界面的期望值。

模型链路分开显示主对话、图片理解、语音识别和语音合成。每条链路有独立模型和地址，未配置的环节在运行时会被跳过或回落到主模型，界面会明确标注“未配置”。

行为路由有三个模式：

- `off`：模型独立决策，图谱完全不参与；
- `hint`：模型仍然决策，图谱补充一段有界参考；
- `graph`：图谱给出立场，模型负责表达。

如果模式选了 `hint` 或 `graph`，但快照路径为空、文件不存在或格式错误，运行时会自动回落到 `off`。界面会把这种回落写出来，而不是显示一个假的“已启用”。“验证快照可用性”会用运行时同一个加载器真正加载一次快照，返回的是证据而不是猜测。

页面下方的“可用图谱产物”列出 `data/private/derived` 下的快照目录和 manifest 摘要，可以直接把某个产物设为当前快照。所有开关都写入 `.env`，保存后必须重启 Bot 才生效；页面不会假装热切换。

“测一次模型连通”会真的发一条 `max_tokens=1` 的请求。**配置了不等于能用**：之前那套地址整个返回 502，而页面照样显示“已配置”。这个按钮会花掉一个 token，换回真实答案——连通时显示实际服务的模型名和耗时，失败时把 HTTP 状态和上游原话（密钥无效、余额不足、模型不存在、限流、连不上）直接摊开。密钥只在服务端读取，不会出现在任何响应里。

## 界面设计约定

控制台是一块工作台，不是一张宣传页。下面这些约定写在 `app.css` 最后一层里，并有 `tests/interfaces/test_design_layer.py` 守着，改动时会被检查：

- **一种底色、一种墨色、一个强调色。** 强调色只给主要动作和数据里的关键值，不铺满界面。
- **面与面靠色阶区分，不靠边框和阴影。** 面板在静止状态下没有投影、没有 1px 描边；表格行和表单控件保留细线，因为那是数据边界，不是装饰。
- **三种字号。** 页面标题、正文、辅助信息；正文用满墨色，灰色只给次要说明。数字统一等宽对齐，列右对齐。
- **不使用渐变、毛玻璃、药丸徽章、小号全大写加字距的标签。** 这些是模板感的主要来源，标题上方也不再放装饰性小标签。
- **动效只有一次入场**：面板错峰上浮 14px 加淡入，只用 transform 和 opacity，`prefers-reduced-motion` 下全部关闭。
- **长列表分页，不做内滚。** 表格底部永远完整，页码条给出「当前区间 / 总条数」和页码；
  内滚容器会在面板中间切断一行，既看不清有多少数据，也像是渲染坏了。
- **实时看板只改数字，不重建页面。** 轮询拿到数据后先比结构，结构没变就只重写时钟字段，
  所以不会每 5 秒闪一下，滚动位置和正在输入的焦点也不会丢。
- **编辑有未保存保护。** Skill 编辑器会提示「未保存」，切走前确认；`⌘S` / `Ctrl+S` 保存，`Esc` 取消。
